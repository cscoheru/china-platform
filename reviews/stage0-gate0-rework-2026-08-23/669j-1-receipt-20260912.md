## 调试诊断 (4 bugs fixed in this sub-knife)

knife 669j-1.5-debug 诊断 mart SQL 4 个语法 bug (per `apply_mart_city_669j_1.py`):

1. **comma-less CTE chain**: mart SQL 用 dbt-style `),\nname AS (` 无逗号, PostgreSQL 报 syntax error. 修复: `re.sub(rf"(?<!,)\n{name} AS \(", f",\n{name} AS (", sql)` 用 negative lookbehind 跳过已有 `,` 的位置
2. **trailing comma before SELECT**: `real_data_669j_1` CTE close ` `),` 在 SELECT 前, PostgreSQL 不接受. 修复: line 1165 改成 `)`
4. **4 个 spurious `;` ending**: line 1600/1604/1608/1612 LEFT JOIN ON year IN(...) 末尾 `;` 阻断 SELECT. 修复: `re.sub(r'(AND cp\.year IN \([^)]+\))\s*;', r'\1', text)`
5. **5 CTEs 缺 AS t wrapper** (rd15-rd19: dalian/wuxi/suzhou/xiamen/qingdao): VALUES tuples 4 列 PostgreSQL 命名 `column1/2/3/4`, LEFT JOIN ON `rd15.city_code` 失败. 修复: 选 **INSERT-only 模式**, 不执行 mart SQL (per 669b-i-qingdao UPDATE-only 模式). 这避免了修 5 个 CTE 的侵入性改动
