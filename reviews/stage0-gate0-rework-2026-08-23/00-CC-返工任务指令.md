## 任务结论和目标

Stage 0 首轮验收结论为：**不通过**。你必须继续停留在 Stage 0，完成本指令中的返工和证据补齐。**不得启动、实现或预埋 Stage 1 功能。**

返工目标不是增加文档数量，而是让以下声明能够被独立复现和验证：

1. 四类 PRD 指定样本均完成真实技术验证；
2. 核心 Schema 能在空 PostgreSQL 16 + PostGIS 数据库完整执行；
3. 数据模型满足地域版本、指标口径、来源定位和修订不可变要求；
4. 默认测试命令能够直接通过，测试确实调用实现且不能用永真断言制造绿灯；
5. 提交一个严格的 8—12 周 MVP，而不是把 22—32 周长期路线图称为 MVP；
6. 最终总结与工作区实物、命令、测试结果完全一致。

- 不批量抓取全国市县数据。
- 不建立官员能力总分、总排名或隐性综合分。

- 不绕过验证码、访问控制、付费墙或网站明确设置的限制。

## 执行顺序

必须按顺序执行。前一项未完成时，不得用后续文档包装成“Stage 0 完成”。

### 0. 建立真实基线

1. 运行并保存：

   ```bash
   git status --short --branch
   git diff --stat
   git diff --cached --stat
   rg --files | sort
   ```

2. 识别用户已有修改、未跟踪文件和被 `.gitignore` 忽略的样本。
3. 不重置、不覆盖、不删除不属于本次返工的内容。
4. 建立最终物料清单，至少记录：路径、文件类型、大小、SHA-256、生成或获取方式、是否受版本控制管理。

### 1. 补齐四类真实代表样本

PRD 指定类型必须逐字满足：

1. 国家统计年鉴表；
2. 省级统计年鉴表；
3. 地市统计公报；
4. 真实扫描 PDF 表格。

具体要求：

- Spike 1 当前国家月度报告可作为额外样本保留，但不能替代国家统计年鉴。
- Spike 2 当前湖北月报可作为额外样本保留，但不能替代省级统计年鉴。
- Spike 3 深圳统计公报可保留，需继续保证逐行可回源。
- Spike 4 必须通过合法来源或用户授权上传取得至少一个真实、图像型扫描 PDF。若仍无法取得，Stage 0 必须保持 `BLOCKED`，不得宣称四类完成或 OCR production-ready。

每个指定样本必须交付：

- 原始文件或合规的可重复获取方式；
- 原始 URL、来源机构、页面或文件标题；
- 获取时间、发布时间和统计期；
- 原始文件 SHA-256；
- 表格、sheet、页码、单元格、段落或 bbox 定位；
- 指标原名、单位、统计口径、脚注或 caveat；
- 提取方式和置信度；
- 缺失原因、修订状态、校验状态；
- 提取结果 JSON；
- 对应的正例、负例和边界测试。

扫描 PDF 还必须报告：

- 页码和 DPI；
- OCR 引擎及版本；
- 每个单元格或词块的 bbox 与置信度；
- 已知真值对照、单元格准确率和人工抽查结果；
- 低置信、缺单位、缺值的复核队列结果。

### 2. 修复 Schema，使其可执行且满足 PRD

必须至少完成以下修改：

1. 将 GiST 排他约束所需扩展改为 `btree_gist`。
2. 对 `DATE` 有效期使用语义明确的 `daterange`，并补 `valid_from <= valid_to` 检查。
3. 消除 `analysis_run` 对尚未创建表的前向外键引用。
4. 修复非法 `COMMENT ON TABLE comparison_group ...` 语法。
5. 新增 PRD 要求的时变 `geo_relation`，包含关系类型、有效期、来源和防重叠约束。
6. 为 `indicator_definition` 补齐地域范围等 PRD 最低字段。
7. 让 `observation` 明确关联 `indicator_methodology_version`。
8. 重新设计 observation 自然键，使不同来源和不同口径版本能够并存。
9. 为所有来源、来源定位、来源登记和 ingestion 引用建立真实外键。
10. 事实记录的 `source_location_id` 必填；`source_location` 至少有一种有效定位方式。
11. 为置信度、SHA-256、revision number、有效期等关键字段增加检查约束。
12. 落实原始文档、observation 和 revision 的不可变或 append-only 规则；不得使用会销毁历史的级联删除。
13. 建立“当前有效观测值”视图：有 revision 时选择最新修订，无 revision 时回退初始 observation。

Schema 必须在一个全新 PostgreSQL 16 + PostGIS 数据库中复验：

```bash
psql -v ON_ERROR_STOP=1 -f schema/01-core.sql
```

必须提交完整命令、数据库版本、退出码和结果。只做静态阅读不能称为“可执行”。

数据库负例测试至少覆盖：

- 重叠地域或口径有效期被拒绝；
- 孤儿 source/source_location 被拒绝；
- 空定位被拒绝；
- 非法置信度和哈希被拒绝；
- UPDATE/DELETE 不可变事实被拒绝；
- 删除父记录不能清除修订历史；
- 最新 revision 选择正确；
- 两个独立来源可以保留同一指标、地区和时期的不同观测。

### 3. 修正数据语义和逐行可追溯性

#### 湖北期间语义

当前成果同时使用 `1-6月`、`上半年`、`cumulative_half_year` 和 `Q2_ONLY`。脚注“GDP、居民收入为季度数”不足以自动推出“仅第二季度”。

你必须：

1. 从来源说明、统计局口径或数据所有者确认其真实含义；
2. 在确认前移除强制 `Q2_ONLY` 结论，标记为待核验 caveat；
3. 逐行保存 period、period_type、脚注引用和 caveat；
4. 增加防止 H1 累计与 Q2 单季混淆的测试。

#### 缺失值

Spike 1 目前把 `…`、`—` 等缺失单元格直接丢弃。必须改为保留 observation，并记录：

- `value = null`；
- `raw_value`；
- `missing_reason`；
- 原始单元格定位；
- 适当的校验或复核状态。

#### 省级逐行血缘

省级结果的每一行必须新增并测试：

- sheet 和 cell/row locator；
- source document/hash 引用；
- period 和 period type；
- confidence；
- footnote/caveat reference；
- extraction method。

### 4. 修复测试和复现方式

必须完成：

1. 默认命令直接通过，不依赖评审方额外猜测 `--import-mode=importlib`：

   ```bash
   python3 -m pytest -q -p no:cacheprovider
   ```

2. 消除四个同名 `test_extract.py` 的收集冲突，可通过唯一模块名、包结构或正式 pytest 配置解决。
3. Spike 1—3 的测试必须调用对应提取函数，不能只读取预生成 JSON。
4. OCR 的 `needs_review` 条件必须是：低置信、缺单位或缺值任一成立即进入复核队列。
5. 删除所有永真断言，例如 `len(cells) >= 0`、`len(rows) >= 0`、`missing <= total`。
6. OCR E2E 必须断言至少 N 个已知行，并核对已知指标、值、单位、bbox、confidence 和 review queue。
7. 修正 OCR 输出目录，统一写到仓库约定的 `data/extracts/04-scanned-pdf/`。
8. 所有路径基于 `__file__` 或仓库根解析，禁止硬编码 `/Users/kjonekong/...`。
9. 提供明确、最小、可重建的 Python 和系统依赖说明，包含 Python、pytest、openpyxl、BeautifulSoup/lxml、Tesseract、语言包、poppler 等真实版本。
10. 每个测试结果记录完整命令、退出码、passed/failed/skipped 和真实耗时。

现有 22—32 周内容只能保留为长期路线图。另行给出一个严格 8—12 周 MVP，必须包括：

- 明确的 MVP 用户和首个研究问题；
- 逐周任务；
- 每项依赖；
- 每项验收标准；
- 风险和触发指标；
- Schema、数据、采集器、发布和分析方法的回滚触发条件与动作；
- 明确排除项；
- Gate 进入和退出条件。

PRD 的阶段基线不得静默改写。若建议先做江苏单省或缩小 Stage 1 范围，必须提供“PRD 基线 / 建议偏差 / 原因 / 影响 / 需要用户批准的决策”对照表。在用户批准前，文档继续以 PRD 为基线。

### 6. 修正文档和风险状态

必须统一并修正：

- `%` 表示百分比，`ppt` 表示百分点；
- PRD 治理观察维度数量及其映射；
- 上传者声明与来源等级核验分离，未经平台核验的上传资料不得自动成为 S0；
- `已识别 / 已设计 / 部分验证 / 已缓解 / BLOCKED` 风险状态；
- R13—R16 是正式登记、合并到既有风险，还是删除重复项；

真实扫描样本未通过前，R04、R08、R11 不得标为已缓解。

### 7. 重写最终总结和证据包

不要沿用旧行数、旧状态或手工估算。最终总结必须从最终工作区重新核对，并包含：

1. 做了什么；
2. 没做什么；
3. 实际修改文件清单；
4. 每个文件的路径、大小、行数或记录数；
5. 运行过的完整命令；
6. 命令退出码和测试结果；
7. 四类指定样本的真实结果；
8. 未解决风险；
9. 需要用户决策的问题；
10. 下一阶段建议；
11. Stage 0 最终状态。

禁止把脚本命令和测试结果写在同一条注释里，除非该命令确实同时执行了两者。禁止把 20+10+20+30 分钟写成 16 分钟。
