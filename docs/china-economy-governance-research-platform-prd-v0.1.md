# 中国经济与区域治理研究平台 PRD v0.1

- 文档日期：2026-08-23
- 文档状态：供 Claude Code（下称 CC）执行的首版需求书
- 项目性质：长期研究与数据平台，近期服务于用户的中国咨询工作，长期可扩展为面向更多客户的研究产品
- 历史起点：2001 年；中国于 2001 年 12 月 11 日正式加入世界贸易组织，因此年度序列原则上从 2001 年开始，必要时补充 1995—2000 年作为基线

## 0. 执行摘要

本项目总体合理、具有长期价值，但必须被定义为“持续建设的数据与研究基础设施”，不能被当作一次性爬虫、一个宏观经济仪表盘，或由大模型自动给地方官员打分的项目。

可行性分层如下：

1. 国家层面：高可行。国家统计局、财政部、海关、人民银行、部委公报和政府工作报告可以形成较完整的年度、季度和月度序列。
2. 省级层面：较高可行。31 个大陆省级地区的主要经济社会指标可以从国家统计局地区数据、省级统计年鉴、公报及各部门网站获取。
3. 地级层面：中等可行。多数地级市有统计年鉴或公报，但格式、指标、历史连续性和网页稳定性差异很大。
4. 县区层面：低至中等可行。公开数据分散、缺失较多，行政区划变化频繁，部分历史年鉴只有扫描 PDF 或没有公开电子版。应按需求和价值逐步扩展，而不是首期全量覆盖。
5. 官员与政府行为：事实性信息可做，包括任免、任期、职务、政府工作报告、政策文件、会议活动、预算执行、项目审批和完成情况；“是否尽职”无法直接观察，只能形成有证据、可解释、带不确定性的治理效能观察。

本项目必须坚持四个原则：

- 事实、计算结果、模型推断和研究者判断严格分层；
- 每一个数据点和结论都可追溯到来源、版本和抓取时间；
- 不把经济增长简单归因于单一官员或单项政策；
- 先建设国家—省级—样本城市的可用闭环，再扩展到全国地级市和区县。

建议首个可用版本用 8—12 周完成，覆盖国家、31 个大陆省级地区和 3—5 个试点省份中的重点城市；全国地级市和区县的历史重建可能需要 9—18 个月持续投入，具体取决于数据授权、PDF/OCR 工作量和人工校验资源。

## 1. 项目目标

### 1.1 总目标

建设一个能够持续回答以下问题的研究平台：

- 中国经济从加入 WTO 以来经历了怎样的增长、结构变化和区域分化？
- 当前国家、各省、市和重点区县的经济运行处于什么状态？
- 一个地区的发展基础是什么，包括区位、资源、产业、人口、人才、财政和基础设施？
- 当前发展动力、约束、风险和政策重点是什么？
- 地方政府提出了什么目标，投入了什么资源，执行到什么程度，产生了什么结果？
- 在控制初始条件、全国周期、上级政策和外部冲击后，该地区表现相对可比地区如何？
- 官员任期与政策、项目和结果之间存在什么时间关系？哪些只是相关性，哪些具备较强的因果识别条件？
- 中国中央和地方政府的运行效能可以从哪些公开证据观察，证据强度和不确定性如何？

### 1.2 首期使用对象

- 用户本人：用于中国企业咨询、行业研究、区域选择、文案和战略分析。
- 后续研究人员：查询数据、核查来源、制作比较和形成报告。
- 长期潜在客户：获得区域画像、专题报告、监测预警和定制比较。

### 1.3 非目标

首期不做以下事项：

- 不建立不可解释的“官员能力总排名”；
- 不从私人社交账号、泄露资料或非公开个人信息建立人物画像；
- 不把新闻报道数量、会议次数、招商签约额直接当作实际绩效；
- 不让大模型直接改写原始统计数据；
- 不以抓取网页数量作为完成标准；
- 不在首期覆盖全国所有区县的全部指标；
- 不绕过验证码、访问控制、付费墙或网站明确设置的技术限制；
- 不把 DeepSeek Harness（DSH）或任何 Agent 框架作为核心数据仓库或统计计算引擎。

## 2. 研究范围

### 2.1 时间范围

- 核心年度序列：2001 年至最新完整年度。
- 历史基线：对关键指标尽可能补充 1995—2000 年，用于识别加入 WTO 前后的变化。
- 当期监测：国家和省级采用月度、季度和年度；地级市按公开频率；区县原则上采用年度。
- 每个数据点保存“统计期”和“发布日期”，两者不得混淆。

### 2.2 地理范围

- 国家：中国大陆总体。
- 省级：31 个大陆省、自治区和直辖市。
- 地级：地级市、地区、自治州、盟。
- 县级：市辖区、县、自治县、旗、县级市等，按优先级逐步纳入。
- 香港、澳门和台湾使用不同统计制度，首期建立独立来源登记和数据口径，不与大陆地区自动拼接比较。

### 2.3 行政区划版本

必须建立时变行政区划模型，记录：

- 规范区域 ID；
- 行政区划代码；
- 统计用区划代码；
- 区域层级与类型；
- 上级区域；
- 有效起止日期；
- 撤县设区、撤地设市、合并、拆分和更名；
- 前身和继承关系；
- 数据是否按当年边界、当前边界或可比口径发布。

禁止用当前行政区划代码直接覆盖历史数据。跨期比较时必须声明边界是否可比。

### 2.4 主题范围

首期核心主题：

1. 总量与增长：GDP、增加值、产业结构、劳动生产率。
2. 需求结构：消费、投资、出口、进口、房地产。
3. 产业结构：农业、制造业、服务业、重点行业、产业集群。
4. 企业活力：企业注册、民营经济、国有经济、外商投资、上市公司和创新主体。
5. 人口与人才：常住人口、户籍人口、年龄结构、迁移、就业、工资、教育和高校资源。
6. 财政与债务：一般公共预算、政府性基金、税收、非税收入、土地相关收入、支出结构、债务和转移支付。
7. 金融：信贷、存贷款、社会融资、金融机构和风险事件。
8. 资源与环境：土地、水、能源、矿产、生态、污染、碳排放和自然灾害暴露。
9. 基础设施与公共服务：交通、能源、通信、教育、医疗、养老和住房。
10. 创新与数字化：研发投入、专利、高新技术企业、技术交易和数字产业。
11. 开放程度：外贸、外资、开发区、口岸、跨境电商和国际运输。
12. 政府行为：政策、预算、项目、承诺、执行、公开透明、回应和纠偏。

## 3. 信息分层与证据规则

### 3.1 四层信息模型

平台中的内容必须标记为以下类型之一：

1. `FACT`：来源直接披露的事实或数值。
2. `DERIVED`：通过公开公式计算得到的增速、占比、指数、同类排名等。
3. `INFERENCE`：基于模型、同类比较或事件研究形成的推断。
4. `JUDGMENT`：研究者在明确证据和假设基础上的判断。

任何 AI 生成文字都不得把 `INFERENCE` 或 `JUDGMENT` 写成无条件事实。

### 3.2 来源等级

- S0：法定或一手官方来源。国家统计局、地方统计局、财政部门、海关、人民银行、部委和地方政府正式文件、人大预算决算、审计报告、任免文件等。
- S1：国际组织、正式学术数据库、科研机构和高校发布的可复核数据。
- S2：有合法授权的商业数据库和行业数据库。
- S3：主流媒体、行业媒体和公开研究报告，用作事件线索和补充解释。
- S4：社交媒体、自媒体、论坛和评论，仅用于发现线索，不作为单独定论依据。

核心经济数据优先使用 S0。涉及官员表现、政策效果和争议事件的结论，原则上需要至少两类独立证据，并标注相互矛盾的材料。

### 3.3 数据血缘

每个数据点必须保留：

- 来源机构；
- 页面或文件标题；
- 原始 URL；
- 原始文件哈希；
- 表格、页码、单元格或段落定位；
- 指标原名；
- 单位；
- 统计口径；
- 统计期；
- 发布日期；
- 抓取日期；
- 初值、修订值或终值状态；
- 提取方式：API、HTML、Excel、PDF 文本、OCR 或人工录入；
- 提取置信度；
- 校验状态与校验人。

## 6. 政府运行效能观察框架

### 6.1 名称和边界

首期统一使用“治理效能观察”或“政府运行效能观察”，不使用“官员尽职评分”。原因是公开数据不能直接观察主观努力、内部决策质量和不可公开约束。

### 6.2 六段证据链

1. 条件 `CONDITION`：区位、资源、产业基础、人口、人才、历史债务和全国周期。
2. 承诺 `COMMITMENT`：工作报告、规划、预算和政策文件提出的目标。
3. 投入 `INPUT`：财政、土地、融资、组织资源和政策工具。
4. 执行 `PROCESS`：预算执行、审批时长、项目节点、政策落地、信息公开和问题回应。
5. 产出 `OUTPUT`：设施建成、服务供给、企业和项目落地、就业岗位等直接结果。
6. 结果与风险 `OUTCOME_RISK`：收入、生产率、就业、创新、公共服务、生态、债务、房地产和人口变化。

“发文多、开会多、招商签约多”只能证明活动强度，不能直接证明执行效率或发展效果。

### 6.3 观察维度

- 目标一致性：目标是否明确、连续、可测量。
- 财政执行：预算完成度、支出结构、绩效公开和资金使用稳定性。
- 项目交付：从批准、签约、开工到投产的转化率和周期。
- 经济适应：产业升级、民营投资、创新和开放结构变化。
- 公共服务：教育、医疗、就业、住房、交通和社会保障改善。
- 风险管理：债务、房地产、生态、灾害和财政可持续性。
- 政务透明：数据发布及时性、修订说明、公开完整性和回应质量。
- 政策兑现：工作报告和规划承诺的可验证完成情况。

### 6.4 分析方法

按由弱到强的证据层级使用：

1. 自身趋势：和本地区过去比较。
2. 同类比较：和经济基础、人口、产业、区位相近地区比较。
3. 条件化表现：控制初始条件、全国年份效应、行业结构和上级政策后的相对表现。
4. 面板固定效应：区分长期地区特征和共同年度冲击。
5. 事件研究：观察政策或任期变化前后的动态路径。
6. 双重差分：仅在处理组、对照组和平行趋势条件较可信时使用。
7. 合成控制：针对重大地方政策或冲击构建反事实路径。

回归残差、相对超额表现或任期前后变化均不得被命名为“官员贡献”。建议使用“条件化相对表现”“未解释差异”或“与任期重合的变化”。

### 6.5 任期归因约束

- 记录党委、政府、人大、政协和关键部门职位，不把不同职位混为一谈。
- 同一地区可能存在多人共同决策，必须记录重叠任期。
- 重大项目和产业政策通常跨任期，需记录提出、批准、开工、投产和见效的不同责任时段。
- 结果指标设置 1—3 年或更长滞后，并进行敏感性分析。
- 晋升、调任和媒体评价不能作为绩效的直接验证。
- 对负面事件也要区分长期积累、外部冲击和当期处置。

### 6.6 是否建立综合指数

首期不建立单一总分。先展示维度卡、证据链和同类区间。

如后期建立综合指数，必须同时公开：

- 指标和权重；
- 缺失值处理；
- 标准化方法；
- 对异常值的处理；
- 置信区间；
- 权重敏感性；
- 数据覆盖率；
- 是否受到行政区划和统计口径变化影响。

## 7. 产品功能需求

### 7.1 全国总览

- 加入 WTO 以来的关键经济阶段和结构变化时间线。
- 年度、季度和月度主要指标。
- 产业、需求、财政、金融、人口和外贸结构。
- 当前增长动力、约束和风险清单。
- 中央政策、财政和货币政策时间线。
- 所有图表可查看来源、口径、版本和修订记录。

- 产业结构和产业链；
- 人口与人才；
- 财政与债务；
- 资源与环境；
- 公共服务；
- 对外开放；
- 当前主要问题；
- 领导与任期；
- 政府承诺、政策和重点项目；

### 7.3 地区比较

- 任意选择多个地区和时间范围。
- 名义值、实际增速、人均值、占比和指数化序列。
- 同类地区自动建议，但显示同类选择依据。
- 对不可比指标给予明显警告。
- 支持生成图表、表格、摘要和咨询报告草稿。

### 7.4 历史脉络

- 经济指标、行政区划、官员任期、政策、项目和外部冲击共用时间轴。
- 允许按主题筛选事件。
- 任一结论可回到原始数据和文件。

### 7.5 当前监测与预警

- 根据官方发布时间表检查新数据。
- 识别最新数据、修订数据和缺失发布。
- 监测增速拐点、异常偏离、财政压力、房地产变化、人口变化和政策信号。
- 预警必须显示规则、比较基线和证据，不使用黑箱“风险高”标签。

### 7.6 官员、政策与项目页面

- 官员公开履历和任期时间线。
- 任期内的政策、预算、项目和经济社会指标，但不默认建立因果关系。
- 政府工作报告目标抽取与兑现跟踪。
- 项目从宣布到交付的状态迁移。
- 政策文件的主题、工具、对象、期限和上级政策关联。

### 7.7 研究工作台

- 自然语言提问和结构化筛选。
- 查询数据序列、政策原文、任期和项目。
- 保存研究问题、筛选条件、图表和笔记。
- 生成带引文的报告草稿。
- 导出 CSV、Markdown、图片和后续可扩展的 Word/PDF。

## 8. 技术架构建议

### 8.1 总体分层

1. 原始资料层：保存原始 HTML、PDF、Excel、CSV、图片和抓取元数据。
2. 标准化数据层：统一地域、时间、指标、单位和版本。
3. 分析语义层：派生指标、同类比较、模型结果和治理证据链。
4. 文档检索层：政策、报告、任免、项目和解释性材料。
5. API 层：稳定提供数据、证据和分析结果。
6. 产品层：网页、研究工作台、报告和预警。
7. Agent 层：调用只读研究工具，形成可追溯回答。

### 8.2 推荐技术栈

CC 需先检查现有仓库；若为新项目，可提出等价替代方案，但必须说明理由。

- 数据采集与分析：Python。
- 事务与规范数据：PostgreSQL。
- 地理数据：PostGIS。
- 历史分析和批处理：Parquet + DuckDB，后续按规模评估 ClickHouse。
- 文档原件：S3 兼容对象存储。
- 向量检索：优先 pgvector，规模和性能不足时再独立部署向量库。
- 转换和测试：dbt 或具有同等血缘和测试能力的方案。
- 调度：Prefect、Dagster 或同等工具，首期不必采用复杂集群。
- 后端 API：FastAPI 或与现有技术栈一致的方案。
- 前端：Next.js/React 或与现有产品一致的方案。
- 可观测性：结构化日志、任务运行记录、OpenTelemetry 或等价方案。

### 8.3 DSH 的位置

DSH 只作为可选的研究 Agent 编排层，不进入确定性的 ETL 和统计计算核心。

可以封装以下只读工具：

- `get_indicator_series`
- `compare_regions`
- `get_indicator_definition`
- `get_source_evidence`
- `search_policy_documents`
- `get_official_tenure`
- `get_commitment_progress`
- `get_project_timeline`
- `run_approved_analysis`
- `build_chart_spec`
- `draft_cited_report`

Agent 不得直接执行任意 SQL、访问生产数据库、修改原始数据或发布无来源结论。是否使用 DSH 应在核心数据闭环完成后通过技术验证决定，不得成为 MVP 的前置依赖。

## 9. 数据采集和处理流程

### 9.1 来源登记

所有来源先进入 `source_registry`，记录域名、机构、数据类别、更新频率、授权说明、访问方式、历史覆盖、稳定性和失败处理。

### 9.2 原始资料不可变

每次获取都保存原始文件、时间戳和哈希。上游网页或文件变化时创建新版本，不覆盖旧版本。

### 9.3 提取流程

- Excel/CSV：保留原始 sheet、单元格和脚注。
- HTML：保存正文、表格和页面元信息。
- 文本 PDF：提取文本、表格和页码定位。
- 扫描 PDF：OCR 后保留版面坐标和识别置信度。
- 图表图片：首期只归档，不自动把图形识别值当成正式数据，除非人工复核。

### 9.4 质量校验

- 单位和数量级校验；
- 同表合计校验；
- 同比和增速反算；
- 跨来源一致性检查；
- 时间序列异常检测；
- 修订值和初值冲突检查；
- 行政区划有效期检查；
- 缺失值不得自动写成 0；
- OCR 低置信度进入人工复核队列。

### 9.5 更新频率

- 月度和季度核心指标：每日检查官方发布，发布后 24—72 小时内入库。
- 年度公报和年鉴：按发布周期检查。
- 任免、政策和重大项目：工作日每日或每周检查。
- 历史资料回补：按地区和数据价值排队处理。

## 10. AI 与研究生成规则

### 10.1 AI 可以做

- 文档分类；
- 表格和实体候选提取；
- 指标别名匹配建议；
- 政策目标和措施抽取；
- 工作报告承诺提取；
- 任免和任期候选抽取；
- 异常数据解释候选；
- 带证据的摘要和报告草稿。

### 10.2 AI 不可以直接做

- 未经校验写入正式指标；
- 把缺失值补成看似精确的数字；
- 根据单一新闻判断官员能力；
- 把签约金额当成实际投资；
- 把名义增长当成实际增长；
- 在没有证据时补全政策效果；
- 省略矛盾数据和统计修订；
- 输出未链接证据的事实性结论。

### 10.3 回答格式

研究回答至少分为：

- 结论；
- 事实证据；
- 计算方法；
- 解释与替代解释；
- 不确定性；
- 来源。

## 11. 非功能需求

- 可追溯：正式数据和事实结论来源覆盖率 100%。
- 可复现：分析结果保存代码版本、参数、输入数据版本和运行时间。
- 可回滚：采集器、指标口径和模型更新均有版本。
- 可测试：核心转换和派生指标有自动测试。
- 安全：密钥不进入仓库；采集和 Agent 权限最小化。
- 合规：遵守来源网站规则、数据授权和引用要求。
- 性能：常用地区页面在缓存命中时快速打开；长分析异步执行并显示状态。
- 可扩展：新增地区和指标尽量配置化，而非复制代码。
- 可解释：所有评分、警告和推断显示方法与证据。

## 12. 主要风险与规避方法

### 12.1 统计口径变化

风险：GDP 核算修订、经济普查调整、行业分类变化、固定资产投资口径变化。

措施：指标定义版本化；保存数据 vintage；优先使用最新修订序列，同时允许查看当时发布值。

### 12.2 行政区划变化

风险：撤县设区、合并拆分导致时间序列不可比。

措施：时变行政区划表；禁止静默回填；提供“当年边界”和“可比边界”标识。

### 12.3 地方数据缺失和不一致

风险：地市、区县年鉴不完整，同一指标在不同来源不同。

措施：来源优先级；冲突并存；建立人工裁决记录；缺失就是缺失。

### 12.4 PDF 和 OCR 错误

风险：小数点、单位、负号、表头错位。

措施：版面坐标、规则校验、双引擎比对、抽样复核和低置信度队列。

### 12.5 全量爬取导致范围失控

风险：先写大量采集器，最后仍不能回答研究问题。

措施：围绕核心问题选择指标；每个来源连接器必须服务于已定义的页面或分析任务。

### 12.6 官员和经济结果的错误归因

风险：选择偏差、任期重叠、政策滞后、全国周期和上级资源共同影响。

措施：不建立首期总分；采用同类比较和条件化分析；明确替代解释；显示不确定性。

### 12.7 活动数量冒充执行效能

风险：文件、会议、签约和宣传数量容易获得，但不代表交付。

措施：建立承诺—预算—实施—完成—结果链路；无法验证交付时只标记为活动。

### 12.8 数据授权和网站稳定性

风险：年鉴版权、下载限制、验证码、链接失效和反爬策略。

措施：优先官方公开下载和合法授权；低频率访问；保存原始版本；提供人工上传入口；不绕过访问限制。

### 12.9 AI 幻觉和引用错配

风险：模型把不同年份、地区或同名官员混合。

措施：实体 ID、结构化工具、证据引用门禁、自动一致性测试和人工审阅。

### 12.10 研究立场和确认偏差

风险：先有结论再选数据，或只记录支持某种判断的资料。

措施：预先登记研究问题、比较组和模型；保留反例和相反证据；事实与判断分层。

## 13. 分阶段路线图

### 阶段 0：仓库审计与技术验证，3—5 个工作日

- 盘点现有代码、数据和部署。
- 建立 ADR、数据源登记模板、指标字典模板和行政区划模型。
- 对国家统计年鉴、一个省级年鉴、一个地市公报和一个扫描 PDF 做提取验证。
- 输出 DSH 是否适用的初步判断。
- 本阶段结束后停止，等待审核。

### 阶段 1：国家与省级数据底座，3—4 周

- 国家和 31 个省级地区。
- 2001 年至今核心年度指标。
- 国家和省级最新月度、季度指标。
- 原始资料、数据血缘、版本和质量规则。
- 全国总览和省级基本画像。

### 阶段 2：试点地区与当前监测，4—6 周

- 选择 3—5 个结构差异明显的试点省份，每省 2—4 个城市。
- 建立地级数据连接器和地区画像。
- 建立发布日历、更新任务、异常监测和地区比较。
- 默认候选试点可包括广东、江苏、河南、四川、辽宁，最终由用户按咨询价值调整。

### 阶段 3：官员、政策、项目和承诺，6—10 周

- 公开任免和任期数据。
- 政府工作报告和政策文件。
- 承诺、预算、项目状态和兑现跟踪。
- 官员与事件时间线，仅展示重合关系，不默认归因。

### 阶段 4：治理效能观察与研究 Agent，6—10 周

- 同类地区匹配。
- 条件化相对表现。
- 事件研究和合成控制模板。
- 研究工作台和带来源报告生成。
- 验证 DSH 或其他 Agent runtime 的价值，再决定是否纳入生产。

### 阶段 5：全国地级市和区县持续扩展

- 按客户需求、数据价值和数据可得性排序。
- 每批新增地区都通过覆盖率、口径和 QA 验收。
- 不设不现实的“一次性全量完成”日期。

## 14. MVP 验收标准

### 14.1 数据

- 国家和 31 个省级地区核心年度序列从 2001 年起覆盖率不低于 95%，不可得项有明确缺失原因。
- 每个正式数据点具有来源、统计期、单位和版本。
- 抽样数据与原表一致率不低于 99%；OCR 表格单元格准确率按来源单独报告。
- 同名指标但口径不同不得被自动合并。
- 行政区划变化测试通过。

### 14.2 产品

- 全国页、省级页、比较页、时间线和来源页可用。
- 任意图表可以回到指标定义和原始证据。
- 可导出研究数据和带来源摘要。
- 最新数据更新失败时有明确告警。

### 14.3 AI

- 事实性句子来源覆盖率 100%。
- 测试集中不得出现年份、地区、单位和人物错配。
- 无充分证据时能够拒绝归因或明确表达不确定性。
- Agent 不具有直接修改原始数据和生产数据库的权限。

### 14.4 方法

- 同类比较说明匹配依据。
- 回归或因果分析保存模型、变量、样本和诊断。
- 治理效能页面不输出未经验证的单一总排名。
